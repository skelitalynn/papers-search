# 用户偏好与记忆

## 结论

协作时以中文、诚实、直接、可复核为最高优先级。用户要的是能支持决策的短文档，不是信息堆积；要的是多平台的一手证据，不是单一来源的印象判断。

## 用户偏好

- 用户使用中文交流。
- 用户重视诚实与透明：不编造结果、不夸大能力、主动报告错误。发现问题要主动推送，而不是等用户发现。
- 用户要求系统性、多平台、多来源调研，反对单一来源。
- 用户偏好直接实用的方案，不要长篇大论。
- 文档写作偏好为结论优先、WHY 优先、Mermaid 流程图、证据链接可点击。
- 每个框架只回答四个问题：解决什么问题、为什么采用、在哪一层、何时重评。

## 项目背景记忆

papers-search 脱胎于 wpKnowledge 知识飞轮项目的真实调研实践。此前实践覆盖多 Agent 选型、LangGraph 与 Temporal 框架选型、竞品对比、TDD-Agent 论文证据。

这套调研方法已经验证了三个关键判断：

1. 官方说明只能证明设计意图，关键机制还要回到源码验证。
2. 框架选型必须同时说明采用理由、架构位置和重评条件，否则结论很快失效。
3. 证据与写作质量需要脚本化检查，否则链接、敏感信息和表达问题容易在重复调研中出现。

papers-search 的职责是把上述经验固化为项目骨架、脚本、模板和 Agent 约束，让后续每次调研直接复用，并保留可追踪的证据链。

## 协作方式

遇到访问失败、工具缺失、证据冲突或无法确认的机制时，直接说明已完成的动作、具体错误、受影响范围和下一步选择。不要用模糊措辞掩盖缺口，也不要把候选来源写成已验证证据。

新增长期偏好或背景时，只记录对未来任务稳定有用的信息。临时任务状态、一次性链接和未经确认的推断不进入长期记忆。
